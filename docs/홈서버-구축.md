# 집에서 직접 돌리는 홈서버 구축

> 이 문서는 **통합돌봄**과 **자사몰** 두 시스템 공통입니다. 두 저장소에 같은 내용이 들어 있습니다.
>
> 전제: **학습·검증용**입니다. 어르신 개인정보와 지역화폐 결제가 실제로 오가기 시작하면
> 아래 [언제 클라우드로 옮겨야 하나](#언제-클라우드로-옮겨야-하나) 를 꼭 읽어 주세요.

---

## 왜 홈서버인가

호스팅을 빌리지 않고 집·사무실 PC에서 돌립니다. 두 시스템 모두 외부 라이브러리 없이
Node.js 표준 모듈만 쓰고 데이터베이스가 파일 하나라, 평범한 PC 한 대면 충분합니다.

구상 중이신 **모듈러 엣지 데이터센터 / 로컬 데이터 파운드리**의 가장 작은 출발점이기도 합니다.
지역 데이터를 지역 안에서 처리한다는 구조를 실제로 손에 쥐고 확인해 볼 수 있습니다.

---

## 준비물

| 항목 | 권장 | 비고 |
| --- | --- | --- |
| 컴퓨터 | 지금 쓰시는 윈도우 PC로 시작 | 상시 운영은 미니PC(Intel N100급, RAM 16GB, SSD 512GB) |
| Node.js | **22.13 이상 LTS** | https://nodejs.org 에서 왼쪽 LTS 설치 |
| UPS(무정전장치) | 상시 운영 시 **필수** | 정전 때 데이터베이스 파일이 깨지는 것을 막아 줍니다 |
| 외장 SSD/USB | 선택 | 백업 폴더를 주기적으로 복사해 두면 더 안전합니다 |

**전기료** — 미니PC는 10~15W 수준입니다. 15W로 24시간 한 달을 돌리면 **약 10.8kWh** 입니다.
주택용은 누진 구간에 얹히는 방식이라, 댁의 현재 사용량 구간에 따라 실제 요금은 달라집니다.

## 1단계 — 집 안에서만 쓰기 (지금 바로, 비용 0원)

외부에 아무것도 열지 않습니다. 같은 인터넷(와이파이)에 연결된 기기에서만 접속됩니다.
농가에 노트북 들고 가서 보여드리거나, 담당자가 사무실에서 주문을 접수하는 용도로는 이것으로 충분합니다.

### 1) 폴더 준비

두 저장소를 **나란히** 내려받습니다. 예를 들어 `C:\보성시스템\` 아래에 이렇게 둡니다.

```
C:\보성시스템\
├─ CARE_Community\     ← 통합돌봄   (포트 4000)
└─ my-html-files\      ← 자사몰     (포트 4100)
```

포트를 다르게 잡아 두었기 때문에 **두 시스템을 한 PC에서 동시에 켜도 충돌하지 않습니다.**

### 2) 켜기

각 폴더의 `홈서버\홈서버-켜기.bat` 을 더블클릭합니다. 검은 창이 뜨고 서버가 시작됩니다.

- 통합돌봄 → http://localhost:4000/
- 자사몰 → http://localhost:4100/

이 창은 그냥 켜 두시면 됩니다. **창을 닫으면 서버도 꺼집니다.**

### 3) 같은 와이파이의 휴대폰에서 접속하기

PC의 내부 IP를 알아야 합니다. 검은 창에서 `ipconfig` 를 치고 **IPv4 주소** 를 확인합니다.
`192.168.0.7` 처럼 나옵니다. 휴대폰 브라우저에 이렇게 칩니다.

```
http://192.168.0.7:4000/      통합돌봄
http://192.168.0.7:4100/      자사몰
```

처음에는 윈도우가 "방화벽에서 차단할까요?" 라고 물어봅니다. **개인 네트워크 허용**을 누르세요.
공용 네트워크는 체크하지 않는 편이 안전합니다.

### 4) 자동 시작 · 백업 설정

`홈서버\홈서버-설정.bat` 을 더블클릭하면 메뉴가 나옵니다.

| 번호 | 기능 |
| --- | --- |
| 1 | 컴퓨터를 켜면 홈서버가 자동으로 시작되게 합니다 |
| 2 | 자동 시작 끄기 |
| 3 | 지금 바로 백업 |
| 4 | 상태 확인 (서버가 살아 있는지, 마지막 백업이 언제인지) |
| 5 | 설정 파일 열기 (포트·백업 시각 변경) |
| 6 | 백업 폴더 열기 |

**[1]번을 눌러 두시면** 정전이나 재부팅 뒤에도 알아서 다시 뜹니다.

### 홈서버가 알아서 해주는 것

`홈서버-켜기.bat` 은 서버를 직접 띄우는 게 아니라 **감시 프로그램**을 띄웁니다. 이 프로그램이:

- 서버가 어떤 이유로든 꺼지면 **자동으로 다시 켭니다** (3초 → 실패가 이어지면 최대 60초까지 간격을 늘립니다)
- **매일 새벽 3시 30분에 자동 백업**합니다 (설정에서 변경 가능)
- 백업은 **14일치만 보관**하고 오래된 것은 지웁니다
- 무슨 일이 있었는지 `홈서버\logs\` 에 기록합니다

백업은 단순 파일 복사가 아니라 SQLite 의 `VACUUM INTO` 스냅샷입니다.
**서버가 돌아가는 중에 받아도 깨지지 않습니다.**

## 2단계 — 외부에서 접속하게 하기 (KT 회선 기준)

### KT 가정용 회선의 현실

집 인터넷으로 서버를 바깥에 공개하려면 보통 이런 벽에 부딪힙니다.

| 문제 | 내용 |
| --- | --- |
| 유동 IP | 집 IP는 수시로 바뀝니다. 도메인을 걸어도 계속 끊깁니다 |
| 포트 차단 | 가정용 회선은 80/443 포트가 막혀 있는 경우가 있습니다 |
| 약관 | 가정용 상품은 서버 운영을 제한하는 조항이 있는 경우가 많습니다. **KT 고객센터에 확인해 보시길 권합니다** |
| 공유기 설정 | 포트포워딩을 열면 집 네트워크가 통째로 인터넷에 노출됩니다 |

### 해법: Cloudflare Tunnel

**포트를 하나도 열지 않는 방식**입니다. 집 PC가 바깥으로 연결을 먼저 맺고,
외부 접속은 그 연결을 타고 들어옵니다. 그래서:

- 고정 IP 불필요
- 공유기 포트포워딩 불필요 → **집 네트워크가 노출되지 않습니다**
- 들어오는 포트를 열지 않으므로 **통신사 포트 차단의 영향을 받지 않습니다**
- HTTPS 인증서 자동
- **무료** (도메인 값 연 1~2만원만 듭니다)

### 설치 순서

1. **도메인을 준비**합니다 (가비아·후이즈 등에서 구입)
2. **Cloudflare 계정**을 만들고 그 도메인을 등록합니다.
   안내에 따라 도메인 업체의 **네임서버를 Cloudflare 것으로 변경**합니다 (반영에 몇 시간 걸립니다)
3. Cloudflare **Zero Trust** 로 들어가 **Networks → Tunnels → Create a tunnel** 을 고릅니다
4. 터널 이름을 정하면 **윈도우용 설치 명령(토큰 포함)** 이 화면에 나옵니다.
   그대로 복사해 집 PC에서 실행하면 `cloudflared` 가 서비스로 설치됩니다
5. **Public hostname** 을 두 개 추가합니다

   | 주소 | 연결할 곳 |
   | --- | --- |
   | `care.내도메인.kr` | `http://localhost:4000` |
   | `shop.내도메인.kr` | `http://localhost:4100` |

6. 끝입니다. 이제 밖에서 `https://care.내도메인.kr` 로 들어옵니다

> Cloudflare 화면 구성은 가끔 바뀝니다. 메뉴 이름이 다르면 화면 안내를 따라가시면 됩니다.

### 외부 공개 전에 반드시 할 것

- [ ] **운영자 비밀번호 변경** — 첫 로그인 때 시스템이 강제로 물어봅니다
- [ ] **공급처 초기 비밀번호 변경** (자사몰 `bohueng` / `dahyang` / `jubang`)
- [ ] 자동 시작과 자동 백업이 켜져 있는지 `홈서버-설정.bat` [4]번으로 확인
- [ ] 백업 폴더를 외장 SSD나 클라우드에도 주기적으로 복사

## 백업에서 되돌리기

1. 홈서버를 끕니다 (검은 창 닫기)
2. `홈서버\backups\` 에서 되돌릴 날짜 폴더를 엽니다
3. 그 안의 `.db` 파일을 프로그램의 `data\` 폴더로 덮어씁니다
   - 통합돌봄 → `data\care.db`
   - 자사몰 → `data\mall.db`
4. 자사몰은 `uploads` 폴더도 `public\uploads\` 로 덮어씁니다
5. 홈서버를 다시 켭니다

> `data\` 폴더에 `.db-wal`, `.db-shm` 파일이 남아 있으면 **함께 지우고** 덮어써야 합니다.

## 언제 클라우드로 옮겨야 하나

홈서버로 계속 가도 되는 경우와, 옮겨야 하는 경우를 솔직히 구분해 두겠습니다.

**홈서버로 충분한 단계**

- 화면 검토, 농가 시연, 담당자 교육
- 내부 업무용 주문 접수 (외부 공개 없이)
- 데이터가 날아가도 다시 넣으면 되는 시험 데이터

**클라우드로 옮겨야 하는 단계**

- 어르신의 **건강 관련 정보**가 실제로 쌓이기 시작할 때 — 개인정보보호법상 민감정보입니다
- **지역화폐 결제**를 실제로 받기 시작할 때 — 결제·정산 기록이 끊기면 안 됩니다
- 지자체 사업으로 편입되어 **보안 점검**을 받게 될 때
- 어르신이나 소비자가 **24시간 접속**할 것을 전제로 안내할 때

집이 정전되면 서비스도 멈춥니다. 월 1~2만원 아끼려고 민감정보 유출이나 며칠치 주문 기록 손실을
감수하는 것은 수지가 맞지 않습니다. **옮길 때가 되면 `src/db.js` 한 파일만 교체하면 되도록
분리해 두었습니다.**

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 검은 창이 바로 닫힌다 | Node.js 가 설치되어 있는지, 버전이 22 이상인지 (`node -v`) |
| 휴대폰에서 접속이 안 된다 | 같은 와이파이인지 / 윈도우 방화벽에서 "개인 네트워크" 허용했는지 |
| 포트가 이미 쓰이고 있다고 나온다 | 다른 프로그램이 4000·4100을 쓰는 중입니다. `홈서버-설정.bat` [5]번에서 포트를 바꾸세요 |
| 서버가 자꾸 꺼진다 | `홈서버\logs\` 의 최근 로그를 확인하세요. 재시작 기록과 이유가 남아 있습니다 |
| 백업이 안 생긴다 | `홈서버-설정.bat` [3]번으로 수동 백업이 되는지 먼저 확인하세요 |
| 컴퓨터를 켜도 자동 실행이 안 된다 | `홈서버-설정.bat` [2]번 → [1]번 순서로 다시 등록해 보세요 |
