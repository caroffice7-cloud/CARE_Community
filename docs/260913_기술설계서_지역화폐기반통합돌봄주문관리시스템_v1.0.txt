1. 시스템 개요

목적
보성군 기본소득 지역화폐(회원당 월 20만원 한도)를 결제 수단으로 하여, 거동이 불편한 어르신 등 통합돌봄 서비스 회원이 (1) 통합돌봄 서비스 메뉴(도시락돌봄·생활지원돌봄·건강돌봄·안전주거돌봄·이동돌봄·정서사회돌봄) 신청과 (2) 생활장터 장보기 주문을 하나의 시스템에서 이용하고, 운영자는 회원별 월 한도·사용액·잔액을 관리하며 접수부터 정산까지 처리할 수 있는 통합 플랫폼을 구축한다.

핵심 설계 원칙
- 월 20만원 지역화폐 한도를 시스템의 중심 축으로 삼는다. 모든 신청·주문은 이 잔액 안에서만 이루어진다.
- 돌봄서비스 메뉴판 신청과 생활장터 장보기 주문은 별개 화면이 아니라 하나의 고객 화면 안에서 탭으로 전환되는 통합 경험으로 제공한다.
- 실제 카드 결제 모듈(지역화폐 전용 결제카드 연동)은 1단계에서는 연결하지 않고, "결제 요청 접수" 상태로 시스템을 완결시킨 뒤 추후 교체 가능한 구조로 분리한다.
- 기존 1차 프로토타입(자연사랑지역화폐구매주문관리서비스.html)의 관리자 기능(주문접수 파싱, 처리현황, 가격표 관리, 회원 관리, 정산)을 계승하되, 클라이언트 저장소 방식에서 서버+데이터베이스 방식으로 전환한다.

2. 사용자 유형 및 화면 구성

2-1. 고객 화면 (어르신 본인 또는 가족·보호자가 모바일로 사용)
- 상단 고정 영역: 이번 달 지역화폐 잔액 표시 (예: 이번 달 사용 가능 금액 15만 3천원 / 총 20만원), 사용 내역 요약 링크
- 탭 1. 통합돌봄 서비스: 오늘 제작한 메뉴판 디자인을 기반으로 7개 분류 40개 서비스를 카드형으로 배치하고, 각 항목에 담기 버튼과 수량 선택을 추가. 추천 패키지 4종(안심생활형·식사중심형·건강중심형·자유선택형)을 원클릭으로 장바구니에 담는 기능 포함
- 탭 2. 생활장터 장보기: 기존 프로토타입의 가격표 데이터를 활용해 품목별 담기 기능 제공. 카카오톡 문장 붙여넣기로 주문하는 기존 방식도 유지(고객이 직접 문장을 붙여넣으면 AI가 파싱해 장바구니에 반영)
- 장바구니 겸 신청서 화면: 담은 돌봄서비스와 장보기 품목이 하나의 목록에 합산 표시, 합계 금액과 잔액 대비 초과 여부 실시간 표시
- 신청자 정보 입력: 이름, 생년월일, 연락처, 배송지 겸 방문지 주소, 비상연락처(보호자), 대리 신청 시 대리인 정보
- 개인정보 수집·이용 동의 체크박스 (필수 동의 항목과 선택 동의 항목 구분)
- 제출하기 버튼 → 서버에 신청 데이터 저장 → "접수되었습니다, 담당자가 확인 후 연락드립니다" 안내 및 접수번호 표시
- 결제 영역: 1단계에서는 "지역화폐 카드로 결제 예정" 상태만 표시하고 실제 카드 승인은 연동하지 않음. 2단계에서 실제 카드결제기 연동 시 이 영역만 교체

2-2. 관리자 화면 (운영자용, 기존 프로토타입 계승 및 확장)
- 접수 현황판: 돌봄서비스 신청 건과 장보기 주문 건을 통합한 하나의 목록, 유형(돌봄/장보기) 구분 표시, 상태별 필터(신청접수→결제대기→결제완료→처리중→완료)
- 카톡 문장 파싱 접수: 기존 기능 유지, 회원명 자동 매칭
- 회원 관리: 기존 이름·연락처·배송지·비고 CRUD에 월 지역화폐 한도(기본 20만원, 회원별 조정 가능), 이번 달 누적 사용액, 잔액 컬럼 추가. 월이 바뀌면 사용액 자동 초기화(이월 규칙 반영: 미사용 잔액 최대 20만원까지 1회 이월)
- 가격표 관리: 기존 장보기 품목 가격표(매입가·마진율·판매가) 기능 유지, 돌봄서비스 메뉴 항목별 단가도 동일한 방식으로 관리
- 정산: 회원별·기간별 수납액, 매입원가, 마진 집계, 돌봄서비스와 장보기 항목 구분 집계, CSV 내보내기(지역화폐 사용 내역 증빙용)
- 잔액 관리 대시보드: 전체 회원의 이번 달 사용률, 한도 임박 회원 알림, 잔액 소진 추이

3. 데이터 모델 (핵심 테이블)

회원(Member)
- 회원ID, 이름, 생년월일, 연락처, 비상연락처, 주소, 월 지역화폐 한도(기본 200000원), 등록일, 비고

월별 잔액(MonthlyBalance)
- 회원ID, 연월, 한도금액, 사용금액, 이월금액, 잔액(계산값)

신청/주문(Order)
- 주문ID, 회원ID, 유형(돌봄서비스/장보기), 신청일시, 상태(접수/결제대기/결제완료/처리중/완료/취소), 합계금액, 비고

주문항목(OrderItem)
- 주문항목ID, 주문ID, 항목명(메뉴판 서비스명 또는 장보기 품목명), 분류, 단가, 수량, 소계

메뉴 항목(MenuItem) — 돌봄서비스용
- 항목ID, 분류(식사돌봄/생활지원돌봄/건강돌봄/안전주거돌봄/이동돌봄/정서사회돌봄/AI데이터참여), 서비스명, 설명, 단위, 단가

가격표(PriceItem) — 장보기용, 기존 프로토타입 계승
- 품목ID, 품목명, 매입가, 마진율, 판매가

동의 기록(Consent)
- 동의ID, 주문ID 또는 회원ID, 동의 항목명, 동의 여부, 동의 일시, IP 또는 접속 정보(선택)

결제요청(PaymentRequest) — 1단계는 상태값만, 2단계에서 실제 카드 연동 필드 추가
- 결제요청ID, 주문ID, 요청금액, 상태(요청/승인대기/완료), 향후 카드 연동 필드는 확장 예정으로 비워둠

4. 단계별 구축 로드맵

1단계 (클로드 코드로 우선 구축)
- 고객 화면: 메뉴판 신청 + 장보기 담기 + 정보입력 + 동의 + 제출
- 관리자 화면: 통합 접수 목록, 회원별 한도·잔액 관리, 가격표 관리, 정산
- 백엔드: 서버(API) + 데이터베이스로 신청 데이터 저장, 관리자 화면에서 실시간 조회
- 결제: 실제 카드 연동 없이 "결제 요청 접수" 상태로 완결
- 호스팅: 클로드 코드에서 배포 가능한 호스팅 서비스(예: Vercel 등) 사용, 도메인 연결은 별도 결정 필요

2단계 (추후 확장)
- 지역화폐 전용 결제카드 실 연동 (보성군 보성사랑상품권 카드결제기 API 또는 표준 연동 방식 확인 필요)
- 쿠팡 오픈API 연동으로 장보기 실매입 자동화
- 카카오 비즈메시지 API로 신청 확인·처리 알림 자동 발송

3단계 (장기)
- 정기배송/구독형 돌봄서비스
- 회원별 이용 이력 기반 AI 통합돌봄 데이터 파운드리 연계 (본 시스템에서 수집되는 신청·소비 패턴 데이터를 비식별화하여 활용)

-----

5. 미결정 사항 (클로드코드 착수 전 확인 필요)
- 호스팅 서비스 선택 및 계정 준비 (Vercel, 카페24, AWS 등 중 택일)
- 데이터베이스 종류 선택 (API Layer 분리 여부)
- 관리자 계정 로그인 방식 (단일 관리자 비밀번호 방식으로 우선 시작할지, 다중 계정 권한 분리가 필요한지)
- 개인정보 저장 시 보안 요건(암호화, 접근 로그 등) 수준 결정
- 지역화폐 월 한도 이월 규칝의 시스템 반영 시점 (1단계에 포함할지 2단계롽 미륬지)
