# 보성군 지역화폐 기반 통합돌봄 주문관리 시스템

> 기술설계서 `260913_기술설계서_지역화폐기반통합돌봄주문관리시스템_v1.0` 의 **1단계 범위**를 구현한 것입니다.
> 농업회사법인 히스메이커스 주식회사 · 자연사랑 생활장터 · BMC 마을방송국

보성군 기본소득 지역화폐(회원당 월 20만원 한도)를 결제 수단으로 하여,
거동이 불편한 어르신이 **통합돌봄 서비스 신청**과 **생활장터 장보기 주문**을 한 화면에서 이용하고,
운영자는 **회원별 월 한도·사용액·잔액 관리부터 정산까지** 처리하는 통합 플랫폼입니다.

---

## 1. 실행 방법

준비물은 **Node.js 22.13 이상** 하나뿐입니다. 별도 설치(npm install)가 필요 없습니다.

```bash
node --version          # v22.13 이상인지 확인
ADMIN_PASSWORD=원하는비밀번호 npm start
```

| 화면 | 주소 |
| --- | --- |
| 고객 화면 (어르신·보호자) | http://localhost:3000/ |
| 운영자 화면 | http://localhost:3000/admin |

최초 실행 시 메뉴판 43개 항목, 추천 패키지 4종, 생활장터 가격표 샘플 30건이 자동으로 들어갑니다.

### 환경변수 (`.env.example` 참고)

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | `boseong2026` | 운영자 로그인 비밀번호 — **운영 전 반드시 변경** |
| `PORT` | `3000` | 서버 포트 |
| `DB_PATH` | `data/care.db` | SQLite 파일 경로 |
| `SECURE_COOKIE` | (없음) | HTTPS 운영 시 `1` 로 설정 |

```bash
npm run seed     # 초기 데이터 적재(이미 있으면 건너뜀)
npm run reset    # 메뉴판·가격표를 설계서 기준으로 초기화 후 재적재
```

실제 서버에 올리는 절차(설치·HTTPS·자동 백업·점검표)는 **[docs/DEPLOY.md](docs/DEPLOY.md)** 에 정리해 두었습니다.

## 2. 구현된 기능

### 고객 화면 (모바일 우선 · 큰 글씨/큰 버튼)

- **상단 고정 잔액 바** — 이번 달 사용 가능 금액, 한도, 사용액, 적립 포인트, 사용률 막대
  - 장바구니에 담을 때마다 실시간으로 남는 금액이 줄어들고, 초과하면 빨간색으로 경고
- **탭 1. 통합돌봄 서비스** — 메뉴판 7개 분류 43개 서비스를 카드형으로 배치, 담기·수량 조절
  - **추천 패키지 4종**(안심생활형·식사중심형·건강중심형·자유선택형) 원클릭 담기
- **탭 2. 생활장터 장보기** — 품목 검색·담기 + **카카오톡 주문 문장 붙여넣기 자동 파싱**
- **장바구니 겸 신청서** — 돌봄서비스와 장보기 품목을 하나의 목록에 합산, 소액주문 취급비 자동 적용
- **신청자 정보** — 이름·생년월일·연락처·주소·비상연락처, 가족/보호자 **대리 신청** 입력
- **개인정보 동의** — 필수 2항목·선택 3항목 구분, 동의 일시와 접속 IP까지 기록
- **제출 → 접수번호 발급** — "접수되었습니다, 담당자가 확인 후 연락드립니다" 안내
- **결제 영역** — 1단계는 "지역화폐 카드로 결제 예정(결제 요청 접수)" 상태만 표시

### 운영자 화면

| 메뉴 | 내용 |
| --- | --- |
| 잔액 대시보드 | 전체 사용률, **한도 임박(80%↑) 회원 알림**, 잔액 소진 회원, 사용액 상위 회원, 상태·유형별 집계 |
| 접수 현황 | 돌봄서비스·장보기를 **통합한 하나의 목록**, 유형/상태 필터, 이름·연락처·접수번호 검색, 목록에서 바로 상태 변경 |
| 상세 보기 | 신청 항목, 결제 요청 상태, **개인정보 동의 기록**, 처리 이력 전체 |
| 카톡 접수 | 카카오톡 문장 분석 → 회원 자동 매칭 → 품목 가감 → 접수 등록 (한도 초과 시 확인 후 강제 접수 가능) |
| 회원 관리 | 등록·수정·삭제, **월 지역화폐 한도 개별 조정**, 이월액·포인트·사용액·잔액·사용률, CSV 내보내기 |
| 가격표 관리 | 생활장터 품목의 매입가·마진율·판매가 (판매가 비우면 자동 계산), 표에서 바로 수정 |
| 돌봄 메뉴 단가 | 메뉴판 43개 항목의 단가·**원가**·적립 포인트·설명 수정 및 항목 추가, 항목별 마진율 표시 |
| 정산 | 기간별 수납액·매입원가·마진, 돌봄/장보기 구분 집계, 취소 위약금 집계, 회원별 집계, **CSV 내보내기(지역화폐 사용내역 증빙용)** |
| 설정 | 기본 월 한도, 이월 사용 여부·최대 금액, 소액주문 취급비·기준 금액, 서비스명 |

### 지역화폐 한도 처리 규칙

```
사용 가능 금액 = 월 한도 + 전월 이월액 + 적립 포인트 − 이번 달 사용액
```

- 월이 바뀌면 해당 월 잔액 레코드가 자동 생성되고 사용액은 0부터 시작합니다.
- **이월**: 전월 자기 한도의 미사용분을 1회, 최대 20만원까지 이월(설정에서 끄거나 한도 변경 가능).
- **포인트**: AI 데이터 참여(방언 녹음·구술 인터뷰 등) 적립금은 1P = 1원으로 잔액과 합산되어 결제에 사용됩니다.
- 신청 금액이 사용 가능 금액을 넘으면 접수가 거부됩니다(관리자 접수는 "한도 초과 접수" 선택 시 허용).
- 주문을 **취소**하면 사용액과 적립 포인트가 복원되고, 취소를 해제하면 다시 차감됩니다.

### 취소·환불 규칙

운영 기준(서비스 24시간 전 취소 시 전액 환불 / 당일 취소 시 50% 부과)을 그대로 따릅니다.
서비스 예정일은 현장에서 정해지므로, 담당자가 취소 처리 시 두 가지 중 하나를 고릅니다.

| 선택 | 처리 |
| --- | --- |
| 24시간 전 취소 | 이용료 전액을 잔액으로 복원 |
| 당일 취소 | 이용료의 50%를 위약금으로 부과하고 나머지만 복원 |

위약금은 주문에 기록되고 처리 이력에 사유가 남으며, 정산에서 별도 항목(취소 위약금)으로 집계됩니다.

### 원가와 마진

메뉴 항목마다 **원가**를 입력할 수 있습니다. 돌봄서비스는 인건비가 주 원가이며,
운영 기준상 직접 서비스 인건비는 시간당 15,000~16,000원(가사간병·일상돌봄 바우처 단가 준용)입니다.
원가를 비워 두면 해당 항목의 마진이 매출과 같게 잡히므로, 정산 화면에 **원가 미입력 경고**가 표시됩니다.

## 보안

어르신의 이름·생년월일·연락처·주소와 건강 관련 정보를 다루므로 다음을 적용했습니다.

| 항목 | 처리 |
| --- | --- |
| 화면 출력 | 사용자가 입력한 문장(카카오톡 주문 등)과 서버 메시지를 HTML 이스케이프 후 표시 — 스크립트 주입 차단 |
| 로그인 | 같은 IP에서 10분 내 5회 실패하면 10분간 잠금 (무차별 대입 방지) |
| 세션 | HttpOnly · SameSite=Lax 쿠키, 8시간 만료. HTTPS 운영 시 `SECURE_COOKIE=1` 로 Secure 적용 |
| 데이터베이스 | 모든 질의를 파라미터 바인딩으로 처리 |
| 금액 계산 | 단가·수수료를 클라이언트 값이 아닌 서버 단가로 다시 계산 |
| 동의 기록 | 필수/선택 동의 여부, 동의 일시, 접속 IP를 주문 단위로 보관 |
| 정적 파일 | 경로 상위 이동(`../`) 차단 |

**HTTPS 없이 운영하지 마십시오.** 개인정보가 평문으로 오갑니다. 설정 방법은 [docs/DEPLOY.md](docs/DEPLOY.md) 5장에 있습니다.

## 3. 기술 구성

외부 라이브러리 없이 **Node.js 표준 모듈만** 사용합니다. 설치·빌드 과정이 없어 어떤 서버에서도 `node server.js` 한 줄로 뜹니다.

```
server.js              HTTP 서버 · 라우팅 · 정적 파일 서빙
src/db.js              SQLite 스키마 (node:sqlite 내장 모듈)
src/seed.js            메뉴판 43항목 · 패키지 4종 · 가격표 샘플 · 동의항목
src/lib/http.js        라우터, JSON/CSV 응답, 쿠키
src/lib/auth.js        관리자 세션 (단일 비밀번호 → 2단계에서 다중 계정 확장 지점)
src/lib/balance.js     월 한도·이월·포인트 계산 (시스템의 중심 축)
src/lib/parser.js      카카오톡 주문 문장 파싱
src/lib/csv.js         엑셀 한글 호환 CSV
src/routes/public.js   고객 화면 API
src/routes/admin.js    운영자 화면 API
public/                고객 화면 · 운영자 화면 (바닐라 JS, 빌드 불필요)
docs/                  기술설계서 원본, 배포 가이드(DEPLOY.md)
legacy/                기존 저장소에 있던 게시판 템플릿(미사용, 보존용)
```

### 데이터 모델

`members` · `monthly_balances` · `menu_items` · `price_items` · `packages` / `package_items` ·
`orders` / `order_items` · `consents` · `payment_requests` · `order_logs` · `settings`

설계서의 핵심 테이블을 그대로 따르되, 처리 이력(`order_logs`)과 운영 설정(`settings`)을 더했습니다.

## 5. 운영 전 확인이 필요한 사항

설계서 5장 "미결정 사항" 중 코드로 정할 수 없는 항목입니다.

1. **호스팅** — 현재 구조는 Node를 계속 띄워 두는 서버(카페24 Node 호스팅, AWS Lightsail, Render 등)에 적합합니다.
   Vercel 같은 서버리스에 올리려면 SQLite 파일 대신 외부 DB(Postgres 등)로 바꿔야 합니다. `src/db.js` 한 파일만 교체하면 되도록 분리해 두었습니다.
2. **관리자 계정** — 지금은 단일 비밀번호입니다. 담당자가 여러 명이고 권한을 나눠야 하면 `src/lib/auth.js` 확장이 필요합니다.
3. **개인정보 보안 수준** — 현재는 접근 통제(로그인)와 동의 기록까지 구현되어 있습니다.
   주민등록번호 등 민감정보를 다루게 되면 저장 시 암호화와 접근 로그가 추가로 필요합니다.
4. **정산의 원가** — 메뉴 항목별 원가 입력 기능은 들어가 있으나, **실제 원가는 아직 비어 있습니다.**
   운영자 화면 > 돌봄 메뉴 단가에서 항목별 인건비·자재비를 입력해야 정산 마진이 정확해집니다.
   (입력 전에는 정산 화면에 경고가 표시됩니다)
5. **가격표 샘플** — 생활장터 30개 품목은 **샘플 단가**입니다. 운영 전 관리자 화면 > 가격표 관리에서 실제 매입가로 교체하십시오.
